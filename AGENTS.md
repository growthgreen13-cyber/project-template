# Codex project instructions

- Read `PROJECT.md` and `README.md` before making changes.
- If the slot is unassigned, ask for or infer the project goal from the task; update the project specification before building.
- Prefer small, reviewable changes and clear commit messages.
- Keep dependencies minimal; use the stack the project requires, not a preselected framework.
- Add meaningful tests for new behavior and run available checks before proposing changes.
- Never commit `.env`, credentials, API keys, or private client data.
- Document setup, environment variables, and deployment instructions when applicable.
- Keep `CHANGELOG.md` updated for user-facing changes.
- Use semantic versioning for releases (`vMAJOR.MINOR.PATCH`). Do not create tags without an explicit release request.
- Do not deploy or connect billing/production infrastructure without approval.
